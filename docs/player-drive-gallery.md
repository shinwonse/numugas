# 선수 Drive 갤러리

갤러리 기준 폴더는 기존 공유 폴더 아래의 `선수단` 폴더다. 경로: `공유 폴더 / 선수단 / 선수 이름 / 사진`.

선수 프로필 바로 아래에 3열 정사각형 피드를 표시한다. 페이지를 열면 브라우저가 공개 Drive의 하위 폴더를 탐색하고 **선수 이름과 정확히 일치하는 폴더**를 찾는다. 사진은 해당 폴더 바로 아래의 JPG/PNG/WebP/GIF만 표시한다. 선수 이름은 한글 Unicode 정규화와 앞뒤 공백 제거 후 비교한다. 부분 일치(예: `0425 홍준택.ver`)는 사용하지 않는다.

## 설정

`.env.local` 및 배포 환경에 다음 값을 설정하고 재시작/재빌드한다.

```dotenv
NEXT_PUBLIC_GOOGLE_DRIVE_API_KEY=your_browser_api_key
# 생략하면 현재 팀 공유 폴더(아래 ID)를 사용한다.
NEXT_PUBLIC_GOOGLE_DRIVE_ROOT_FOLDER_ID=1OhJxNckYeGyWeMw3zg872DWOBup7beXJ
```

API 키는 브라우저용 키다. 실제 배포 도메인과 localhost 개발 포트로 웹사이트 제한을 걸고 Google Drive API만 허용한다. OAuth 비밀키나 서비스 계정 키를 NEXT_PUBLIC 변수에 넣지 않는다.

현재 상위 폴더: https://drive.google.com/drive/folders/1OhJxNckYeGyWeMw3zg872DWOBup7beXJ

```text
공유 폴더/
  2026년/ … 기존 경기별 사진
  선수별 사진/
    신원세/
      0905_01.jpg
    홍준택/
      0905_02.jpg
```

공유 루트 바로 아래의 이름 일치 폴더를 우선 사용한다. 직접 일치가 없으면 하위 폴더 전체에서 찾는다. **사진은 선수 폴더 바로 아래**에 둔다. Drive 바로가기/하위 앨범 사진은 따라가지 않는다. 루트에서 같은 이름의 폴더가 여러 개거나, 루트 일치가 없는 상태에서 하위 폴더에 같은 이름이 여러 개면 오류를 표시한다. 선수 이름이 바뀌면 폴더 이름도 맞춰 변경한다. 같은 이름의 선수가 여럿인 경우 이름 자동 매칭 대신 별도 ID 연결 설계가 필요하다.

폴더와 사진은 '링크가 있는 모든 사용자 / 뷰어'로 공개되어 있어야 한다. DB에 폴더 ID를 저장하지 않으므로 **002 마이그레이션은 자동 탐색 기능에 필요 없다.** 기존 컬럼이 있더라도 삭제할 필요는 없다.

## 폴더 29개 한 번에 만들기

Google Drive API 키는 조회용으로만 사용한다. 쓰기 권한이 연결되지 않은 상태에서는 폴더를 만들 수 없다. `scripts/create-player-folders.gs`는 현재 선수 29명의 폴더를 생성하는 Google Apps Script다.

1. 사진을 소유한 Google 계정으로 https://script.google.com/ 에서 새 프로젝트를 만든다.
2. `scripts/create-player-folders.gs`의 내용을 편집기에 붙여넣고 저장한다.
3. 함수 `createPlayerFolders`를 선택하고 실행한다. 첫 실행은 Google 계정의 Drive 권한 승인이 필요하다.
4. 완료되면 기존 상위 폴더 아래 `선수별 사진/선수명`이 생성된다. 기존 선수 폴더가 다른 하위 경로에 있으면 재사용한다. 기존 사진을 이동/복제하지 않는다.

스크립트를 다시 실행해도 기존 폴더를 재사용한다. 중단 후에도 재실행할 수 있다. 기존 동명이름 폴더는 사전에 오류 처리한다. 상위 폴더의 공유 권한을 상속하므로 생성 후 로그아웃 상태에서 접근 가능 여부를 확인한다. 새 선수는 스크립트의 PLAYER_NAMES에 추가하거나 Drive에서 직접 폴더를 만들면 된다.

## 요청량 및 갱신

- 사진은 별도 탭 없이 표시한다. 프로필 아래에 통산 기록을 기본 표시하고, 세부 기록을 펼치면 연도별 기록과 차트를 볼 수 있다.
- 폴더만 검색하며 공개 API 권한에 맞게 부모 폴더 하나씩, 동시에 최대 3개를 조회한다. 탐색 범위는 최대 1,000개(루트 포함)이며 초과하면 오류를 표시한다.
- 선수별 폴더 검색 결과를 React Query로 10분 캐시한다. 루트 바로 아래 선수 폴더는 한 번의 목록 조회로 찾으므로 경기 아카이브 전체 탐색을 생략한다.
- 폴더 생성 직후 빈 상태의 **다시 확인** 버튼을 누르면 캐시를 기다리지 않고 재검색한다. 그 외에는 캐시가 만료된 뒤 선수 페이지를 다시 방문하거나 새로고침한다.
- 사진 목록은 9장씩 10분 캐시. 창 포커스/네트워크 재연결에 따른 자동 재조회와 자동 재시도는 하지 않는다.
- 그리드는 API의 thumbnailLink로 미리보기를 직접 표시한다. 첫 3장은 우선 로드하고 나머지는 브라우저 지연 로딩을 사용한다. 가능하면 링크의 크기 접미사를 640px로 조절하며, 실패하면 API에서 새 기본 링크를 받아 한 번 재시도한다. 썸네일 링크는 영구 저장하지 않는다.
- 확대 화면은 좌우 chevron, 키보드 방향키, 모바일 좌우 스와이프로 이동한다. 세로 스크롤과 멀티 터치는 사진을 넘기지 않는다.
- 원본은 확대할 때만 `files.get?alt=media` → Blob URL로 받는다. 다운로드 중에는 미리보기를 표시한다. 원본 재열기는 5분간 미사용 캐시를 활용한다.
- Supabase Storage, 서버 이미지 중계, Next.js 이미지 최적화를 사용하지 않는다. 그리드에서는 원본 파일을 받지 않는다. 썸네일 표시 실패 시에도 자동으로 대용량 원본을 다운로드하지 않는다.

기존 선수 정보와 기록은 Supabase에서 그대로 조회한다. 이 구조는 Drive API의 실제 프로젝트 할당량과 정책을 따르며 무료·무제한을 보장하지 않는다.

## 검증

```bash
node --test tests/google-drive.test.mjs
```

실제 배포에서는 API 키의 도메인 제한, 공개 폴더 검색, 그리드의 썸네일 응답과 확대 시에만 발생하는 `alt=media` 응답을 확인한다. `/_next/image`나 자체 `/api`로 갤러리 파일이 전달되지 않아야 한다. 현재 이름에 해당하는 폴더가 없으면 빈 상태가 정상이다.
